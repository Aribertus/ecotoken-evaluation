# Ecotoken: evaluation code and data

Companion repository for the article

> Carlini, R., Pareschi, R., Salzano, F., and Testa, B. *A Multi-Asset Architecture for Environmental Externality Tokenization: Design and Implementation in the Ecotoken Platform*. Submitted to *Frontiers in Blockchain*, Research Topic "Blockchain Technology for Energy Optimization" (2026).

It contains everything needed to reproduce the evaluation reported in the article:

| Folder | Article section | Content |
|---|---|---|
| [`simulation/`](simulation/) | Section 7.4, Tables 4–6, Figures 5–6 | Economic simulation of tokenization for two representative asset owners, built entirely on public data |
| [`benchmark/`](benchmark/) | Sections 7.1–7.3, Table 3, Figure 4 | Per-transaction measurements of the token lifecycle on the Algorand TestNet |

The Ecotoken platform itself is proprietary and is not part of this repository; it can be accessed through the demonstration account described in the article's Data Availability Statement.

## Economic simulation

Two cases are modelled:

- **Case A:** a 60 MWp utility-scale photovoltaic plant in southern Italy that monetizes Guarantees of Origin (GOs) through the platform.
- **Case B:** a plastic recycling facility outside the EU that monetizes carbon credits (Verra VMR0007) and plastic credits (Verra PWRM0002), standalone or with certification costs shared across aggregated facilities.

Every parameter is set from a public source or stated as an assumption (low / central / high values in the `PV` and `REC` dictionaries at the top of `model.py`; sources are listed in Table 4 of the article). The platform fee is a swept parameter (2–10%), not a commercial figure. Uncertainty is propagated with a Monte Carlo analysis of 20,000 draws using a fixed random seed, so results are exactly reproducible.

### Reproducing the results

Requires Python 3.10 or later.

```bash
pip install -r requirements.txt
cd simulation
python model.py      # writes results.json (all figures quoted in the article)
python figures.py    # writes figures/fig_pv_breakeven.* and figures/fig_rec_aggregation.*
```

`results.json` as committed is the output used in the article; rerunning `model.py` reproduces it identically. Tested with Python 3.11, NumPy 2.4 and Matplotlib 3.10.

| Output | Article |
|---|---|
| `results.json` → `pv_scenarios`, `pv_yield` | Table 5 and the yield comparison in Section 7.4 |
| `results.json` → `rec_scenarios`, `rec_carbon_only`, `rec_plastic_only` | Table 6 |
| `results.json` → `rec_size` | Figure 6 (standalone vs. aggregated facility) |

## TestNet benchmark

On 26 September 2026, the full lifecycle of an Algorand Standard Asset configured as in the platform (one decimal place; manager, reserve, freeze and clawback held by the platform wallet) was executed 30 times under each of two submission regimes, using the same library as the platform backend (Java `algosdk` 2.5.0) against the public AlgoNode TestNet endpoints. All 480 transactions were confirmed.

| File | Content |
|---|---|
| `benchmark/back-to-back.csv` | Each transaction submitted as soon as the previous one is confirmed |
| `benchmark/random-arrival.csv` | Random wait of 0–3 s before each transaction, so submissions are not synchronized with block production |
| `benchmark/summaries/` | Run summaries generated by the benchmark tool (in Italian) |
| `benchmark/burn-transaction.png` | The burn transaction shown in Figure 4 |

Each CSV row is one operation. The commented header lines (in Italian) describe the columns; in English:

| Column | Meaning |
|---|---|
| `iteration` | Repetition number (1–30) |
| `op` | Operation: `asset_create`, `fund_account`, `opt_in`, `asset_transfer`, `account_info`, `account_txns`, `asset_burn`, `opt_out`, `close_account`, `asset_destroy` |
| `kind` | `tx` for an on-chain transaction, `read` for a read-only query |
| `tx_id` | Transaction identifier on the Algorand TestNet |
| `params_ms`, `sign_ms`, `submit_ms`, `confirm_ms` | Time to fetch suggested parameters, build and sign, submit, and wait for confirmation (ms) |
| `total_ms` | End-to-end time: the sum of the four phases for transactions, call duration for reads (ms) |
| `last_round`, `confirmed_round`, `rounds` | Network round at preparation, round of confirmation, and blocks waited |
| `fee_microalgo` | Fee paid, in microALGO (1000 = 0.001 ALGO) |
| `indexer_lag_ms` | Delay between confirmation and visibility on the indexer (ms), where measured |
| `explorer_url` | Link to the transaction on the Lora TestNet explorer |

Every transaction can be inspected independently on the explorer; all were sent from the wallet [`NWH5QTN2…IKJ2FNY`](https://lora.algokit.io/testnet/account/NWH5QTN2APQMCW5UU4QJAYMWFCZYS6BMTNJSPBJDH2JBZGL7NUZIKJ2FNY).
